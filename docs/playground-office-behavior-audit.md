# Playground Office 行为核对

核对日期：2026-11-10。对象是 Playground 当前已经开放的操作，以及用户指出的 Word 标尺、左侧选行、字体和缩放问题。参考 Windows 桌面 Office 的公开说明与截图；没有运行 Microsoft Word／Excel／PowerPoint 实机对照，不能据此声明完整 Office 行为兼容。

## 参考依据

- Microsoft [Using the ruler in Word](https://support.microsoft.com/en-us/word/using-the-ruler-in-word)：标尺位置、缩进和制表位含义。页面中的桌面截图用于检查标尺与文档视口的关系，没有复用其图片或代码。
- Microsoft [Add and edit text](https://support.microsoft.com/en-us/word/training/add-and-edit-text)：左侧点击选行，以及对选中文字应用字体、字号与基本格式。
- Microsoft [Change the font size](https://support.microsoft.com/en-us/office/fonts/change-the-font-size)：允许直接输入字号；Word 为 1～1638、半磅，Excel 为 1～409、半磅，PowerPoint 为 1～3600、十分之一磅。
- Microsoft [Keyboard shortcuts in Word](https://support.microsoft.com/en-us/accessibility/word/keyboard-shortcuts-in-word)：Ctrl+Y 重做，Ctrl+E／L／R 对齐，以及已有的 Ctrl+B／I／U 与 Ctrl+Z。

## 已发现并修正的问题

| 操作 | 原问题 | 当前行为与验证 |
| --- | --- | --- |
| Word 水平／垂直标尺 | 直接叠在纸张上，跟随整张纸移动 | 放入文档视口上方和左侧的独立栏；水平位置匹配纸张，垂直位置匹配可见页；按页面尺寸、边距、缩放绘制厘米刻度，连续视图隐藏垂直刻度。验证纸张外的几何位置、滚动、125% 缩放、预览／编辑切换和显示开关。 |
| Word 左侧选行 | 指针形状不符合用户要求，编辑区的浏览器光标还可能覆盖它 | 仅在左侧选择区使用朝右上方的镜像箭头，移回正文恢复文字光标。点击选实际可见行，软换行和 emoji 不按源段落或 UTF-16 单码元截断；拖动跨行、Shift 扩选、双击段落、三击／Ctrl 单击全文均使用原生选区，不产生修订。 |
| Word 字体读值 | 拉丁文字也优先显示东亚字体角色 | 按实际文字作用域读取 ascii／hAnsi／eastAsia／cs，保留源字体名；混合字体不伪造单一值。原生中文字体 DOCX 中的拉丁片段读值已验证。 |
| 字体选择／字号输入 | 只能选固定列表，字号范围过窄；Firefox 计算像素的量化使 15.5 磅读回 15.49 | 字体和字号改为可输入、可筛选的字段；Enter 或列表选择提交，Esc 取消；按三种格式分别校验字号范围。读值优先保留与计算结果相符的明确字号，避免像素量化引起漂移。测试选区保留、小数字号、非法值、列表键盘操作和窄屏边界。 |
| 字体看似未生效 | 缺失字体被替代但没有就近提示；渲染投影可能恢复被替代前的字体属性 | 字体字段提示本机缺失字体，仍保留用户选定的源名称；明确的格式编辑通过源投影记录，再进入原有事务。原生 DOCX 的实际字形变化、全中西文字体角色、DOCX 导出重开，以及 PPT 文本框格式／撤销均有检查。SDK 不下载字体。 |
| 反复修改字体 | 不断新增嵌套 span，使 DOM 与源增长 | 复用完整选中的源文字 span；渲染器派生的文字作用域仍须新建源节点，不能把样式写到会被剥离的显示节点。测试连续切换字体、缺失字体、撤销和导出重开，确保 span 数量不持续增长。 |
| 格式字段提交 | 提交后焦点回到文档又触发 blur，重复提交一次；Tab 进入候选项，Firefox 与异步工作簿提交还可能夺走目标字段焦点 | 同一次字段提交只调用一次格式操作；单次撤销即恢复前一个字体。候选项不进入 Tab 顺序，方向键选项／Enter 应用，Tab／Shift+Tab 在提交完成后移动到相邻字段。地址解析／选择等工作簿交互排队时暂时禁用格式字段，避免还未完成的选区操作抢回焦点；测试实际延迟 Worker 回复再继续操作。 |
| 输入点格式 | 在一个输入点选择字体后，移动到另一个段落仍携带旧的待输入格式 | 光标离开原输入点时清理待输入格式；组合输入期间保留中间状态。测试不产生空修订、移动到标题后按标题格式输入，及已有中文组合输入／冲突回归。 |
| Word 键盘命令 | 已有工具栏对齐／重做没有对应快捷键 | Ctrl+Y 与 Ctrl+E／L／R 接入同一核心事务和历史，快捷键与工具栏相互撤销／重做。 |
| 缩放与标尺开关 | 从编辑切到预览或切换标尺后，布局变化造成视口中心偏移 | 标尺栏在 iframe 挂载前创建，避免重挂载重置文档；稳定视口布局，切换标尺时恢复同一缩放锚点。验证居中、横向平移后缩放、编辑／预览切换，且修订不变。 |
| Excel F2／双击编辑时点字体按钮 | 尚未接通单元格内局部文字格式，却可能按整单元格格式执行 | 双击进入现有输入路径；局部文字编辑期间禁用主功能区格式按钮，完成／取消后恢复整单元格格式。验证单元格输入、取消、字体／字号、撤销和 Worker 会话保持。 |
| 状态栏 | 显示“已打开 · 修订… · 批注…”等调试信息 | Playground 去除可见调试状态；修订和批注仍由原有会话管理。 |
| 返回预览后的多页布局 | 隐藏的预览仍按零尺寸测量分页，移除页间间距并可能触发错误；显现后继续用了无效几何 | 不测量隐藏画布，监听 iframe 显隐。编辑期间暂停隐藏预览重建，返回时从当前修订重建可见预览并等待有效分页。原生分节、长文档、编辑与反复切换均检查纸张坐标、间距与异常。 |
| DOCX 标题／列表回车后输入 | 空标题可能塌陷；后增的分页包装泄漏显示 CSS；不可编辑编号文字干扰原生输入法范围，可能只留下拼音或输入到其他段落 | 空行保留派生行框和输入点，投影实时识别自有包装；编辑中的编号改用 CSS 生成内容。回归检查原生“文字与编号”文档各层列表的分段、实际汉字内容、Unicode 变体序列、事务历史及导出重开，保留严格 CSS／映射校验。 |
| 功能区复用与预览开关 | Office 功能区仅在 Playground 中实现，其他宿主需要重复绘制；预览仍显示编辑面板 | 移入 SDK 的可选 React 入口，连同字体字段、图标与作用域样式一起提供。预览默认收起编辑面板，保留文件、审阅和视图入口。独立宿主不加载 Playground CSS，并检查多个组件实例的格式、回调与焦点隔离。 |

## 仍有差异的范围

| 范围 | 当前边界 |
| --- | --- |
| 标尺编辑 | 只显示刻度与页边距；尚无可拖动的首行／悬挂／左右缩进标记、制表位或页边距调整。不能称为完整 Word 标尺。 |
| 左侧选择区 | 当前覆盖正文可见文字行；表格行选择、拖出视口后的自动滚动尚未实现。指针为自绘镜像箭头，没有验证所有操作系统的原生指针像素。 |
| 字体框 | 没有 Office 的主题字体分组、完整系统字体枚举或悬停实时预览。可输入字体名；本机可用性提示基于浏览器字体度量，不代表逐字形覆盖完整。 |
| Word 功能区 | 段落样式库、清除格式、格式刷、删除线／上下标、缩进、两端对齐、行距、分页／页面设置、页眉页脚编辑等未接通的入口仍禁用；不以展示按钮宣称实现。 |
| Excel 文字编辑 | 主功能区没有接入单元格内局部富文本格式，编辑期间明确禁用；SDK 的高级文字格式面板仍是另一种交互入口。 |
| Excel 缩放与输出 | 网格缩放、原生 XLSX 和工作簿 PDF／PNG 尚未实现，入口禁用；文档包保存重开已支持。R3-17～20 的既定范围未因 UI 调整而关闭。 |
| PPT 与 Excel 高级操作 | 已有命令仍打开项目自身的属性面板／表单，尚未复刻 Microsoft 的所有对话框、上下文菜单、拖拽与快捷键；PPT 动画、切换和放映入口仍禁用。 |
| 快捷键／剪贴板 | 仅声明已接通的命令；完整 Office Key Tips、快捷键全集及系统剪贴板权限行为没有等价验收。 |
| 原生 Office 验收 | 本次依据微软公开说明检查项目浏览器行为。没有 Word／PowerPoint 实机验收，也没有补做被延期的 Excel 合并区域删除对照。既有 LibreOffice 证据不能替代 Microsoft Office 证明。 |

## 本轮检查

新增行为检查位于 [workspace.spec.ts](../tests/browser/workspace.spec.ts)，工作簿入口检查位于 [workbook-playground.spec.ts](../tests/browser/workbook-playground.spec.ts)。覆盖原生 DOCX、Word 协作样例、PPT 文本框以及 Worker 工作簿，不只检查按钮的启用状态。

本地使用一个 Playwright worker 顺序执行 Chromium、Firefox、WebKit。字体／标尺／选行／视口和文字格式的定向检查为 36 项；同时复查共享文字编辑、中文组合输入、冲突、复制粘贴、撤销及 Word／PPT 导出闭环。构建与类型检查使用 2 GiB Node 堆上限，不执行一万行容量套件或启动完整 CI。详细结果保存在忽略提交的 `.cache/office-behavior-audit/`；最终结果应按日志报告，不能把过程中的失败日志算作通过。

本轮结果：共享编辑与输出回归 168 项通过、2 项引擎不适用的组合输入检查跳过；后续键盘与字号精度修复后的最终定向检查 36 项全部通过。另有 4 个工作簿输入相关单元测试文件的 26 项通过。库／Playground 构建、类型检查、架构边界和 `git diff --check` 均通过。重启后的 `0.0.0.0:5174` 已现场检查 DOCX 字体／缩放、PPT 字体／历史以及 XLSX 输入／格式与双击编辑，未出现页面异常；浏览器检查结束后关闭测试浏览器，保留开发服务。

本记录列出已查明问题和当前边界，不是完整 Office 兼容性验收。SDK 的格式支持范围与阶段门槛仍以各格式设计、导入导出文档及验收记录为准。

后续的分页切换与 SDK 功能区迁移检查保存在 `.cache/preview-switch/`：覆盖隐藏预览、多页原生 DOCX 反复编辑／预览、独立宿主与多个功能区实例，以及共享输入、批注和输出回归。延迟 Worker 回复的格式可用性、Tab 导航和样式隔离另有最终三引擎定向检查 12 项通过；SDK 组件可在没有浏览器全局对象时进行 React 服务端渲染。现场开发服务中验证了双页文档的 24px 源页间距、预览编辑面板收起和模式切换修订不变，PPT／XLSX 继续使用 SDK 功能区编辑。

DOCX 回车修复的最终检查保存在 `.cache/docx-enter/`：共享输入、分页、PPT 编辑与 Word 输出回归 200 项通过，2 项非 Chromium 的 CDP 输入法检查跳过；工作台三引擎回车检查 21 项通过（包括 6 次 DOCX 导出重开），“文字与编号”的固定字体视觉基线 1 项通过，核心映射／Unicode 拒绝与历史检查 13 项通过。构建、类型及架构边界检查通过。重启后的开发服务另检查五类标题／列表段落连续回车并实际输入中文，逐段核对汉字、编号、修订及异常，测试浏览器已关闭。
