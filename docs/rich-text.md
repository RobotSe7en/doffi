# 正文富文本输入

R1-11 使用自研的原生浏览器输入适配器，提供连续正文和表格内输入、跨段落替换、分段、字符／段落格式、受支持内容粘贴及中文输入法。工作台通过“编辑正文”和“返回预览与批注”切换同一会话的输入及预览界面。

## 挂载与状态

```ts
import { mountDocumentTextEditor } from "@doffi/editor";

const input = mountDocumentTextEditor(container, session, {
  onError(error) { host.showError(error); },
});
await input.ready;
input.focus();
input.execute({ type: "toggle", property: "bold" }); // 依据当前选区／输入格式开关
input.setZoom(1.25); // 缩放不改来源／修订，保留视口中心位置
input.setRulers(true); // 显示派生标尺，不写入源／导出
// session 由宿主创建与释放。
input.dispose();
```

独立入口接受 `DocumentEditingSession`；普通工作台默认提供输入入口，`editable: false` 可隐藏它。React 包装复用相同组件。正文输入位于独立 iframe，源内容经核心校验且 CSP 禁止脚本执行，宿主代码挂载输入适配器；源文档的脚本、事件处理器和未授权资源不会执行。

核心文档包是唯一可保存来源。DOM、光标和输入法中间态均为派生视图，不单独保存。适配器保留已有节点身份、标签、样式、语义属性及区块间空白；新节点由核心分配身份。字段、原生批注及修订继续引用同一源节点。全篇替换保留文档根及分节容器，页设置与页眉页脚引用不因删除正文而消失。

输入法组合期间不提交修订，组合结束统一提交一次。期间若宿主修改了当前修订，待提交输入以 `RevisionConflict` 拒绝，视图恢复到当前核心源。非法结构、Unicode 边界或预算失败也恢复有效状态。卸载取消中间态、监听、输入视图及资源 URL，宿主会话继续可用。

输入适配器没有独立的持久化撤销历史。输入、格式、批注、脚本和提案共用 `prepare/commit` 及核心历史。Ctrl/Command+Z、Shift+Ctrl/Command+Z 和 Ctrl/Command+Y 使用核心撤销重做；Ctrl/Command+E／L／R 执行已有的居中／左／右对齐。

## 原生输入与显示投影

正文使用与预览相同的 HTML/CSS 渲染。`beforeinput` 提供实际修改范围，DOM Range 完成文本替换、分段和格式操作；组合输入期间允许浏览器暂态修改 DOM，结束时统一校验提交。结构位置与段内 UTF-16 偏移共同恢复选区，保留新段落起点与前一段落末尾的区别。

复制和剪切使用选区内的源 HTML 与文字，保留源字体及支持的格式，避免浏览器计算样式进入剪贴板。粘贴仍先校验再进入画布；剪切与输入共享核心历史。宿主在挂载完成前更新会话时，`ready` 返回当前修订的视图；替换为新的授权图片资源时更新派生 Blob URL，卸载释放。

适配器序列化时恢复源属性，去除编号标签、表格测量列、字体替代及制表位引导符等显示投影。明确的格式命令通过投影记录源属性修改，避免字体替代还原覆盖用户选择；完整选中的源文字 span 可复用，派生文字包装不能充当源节点。分段过程中浏览器克隆的行内祖先也使用原身份恢复源属性。HTML 解析器自动补充的 `tbody` 保持为结构内容。结构归一化移动了文字且无法提供精确证据时，对应批注明确要求重定位。

## 身份保留与精确映射

新增内容操作 `reconcileFragment`：

```json
{
  "op": "reconcileFragment",
  "nodeId": "root",
  "html": "<p data-node-id=\"p\">新文</p>",
  "textEdits": [
    { "nodeId": "p", "from": 0, "to": 1, "expectedText": "原", "text": "新" }
  ]
}
```

它协调目标的子内容：只允许保留基准目标子树内已有且唯一的身份，不接受目标根自身、外部节点或猜测的新 ID。没有身份的新元素由核心分配。完整结果仍通过 HTML、CSS、资源及 Word 引用校验；模型使用该操作时也受请求完整子树范围限制。

`textEdits` 是按实际输入步骤产生的 UTF-16 映射证据，顺序范围与 `expectedText` 对照前序步骤后的文字。核心验证代理对、变体选择符、源文字及最终文字一致性。重复文字使用实际编辑位置，不能通过字符串相似性猜测插入点。缺少映射证据的已改变文字目标显式进入 `needs_reanchor`；纯格式变化且文字及身份不变时保留文字锚点。目标之外受到文字变化影响但缺少证据的祖先也明确失效。

映射证据计入会话操作预算，HTML 与证据共同受事务字节、节点、候选和历史预算约束。准备不改变当前状态，失败整批不变。保留原字体名称与中西文角色；Word 输入只对映射证据标明的新插入文字补充字体作用域，不重新分类已有字符；保留 UTF-16 和变体序列。

## 输入范围与验证

工具栏提供字重、斜体、下划线、颜色、字体、字号及段落对齐；`formatState()` 和 `onFormatStateChange` 供宿主读取当前选区，按中西文作用域报告源字体，混合值不强行选定单一格式。连续字符格式操作保留选区；关闭部分文字下划线时保留其他文字的下划线。在折叠输入点选择的待输入格式不单独产生修订，光标移开时清理，组合输入期间保持。Enter 分段，Shift+Enter 换行；直接包含行内内容的单元格内 Enter 换行，Tab／Shift+Tab 在已有单元格间移动。当前编辑正文域；页眉、页脚和原生批注正文继续在预览中显示。

粘贴先在不连接页面的模板中读取，通过同一核心 HTML/CSS 和资源校验后才交给输入视图。复制得到的身份被移除并由核心重新分配。单次文本或 HTML 粘贴上限为 1 MiB，另外受核心预算约束。不支持的结构、样式、资源及输入操作明确失败。拖放不作为未经校验的插入入口。

浏览器验收使用真实 Chromium 组合输入，覆盖重复文字锚点、中文与 emoji／变体序列、跨段落、表格、格式、粘贴、冲突、全篇替换、卸载及 Playground 下载重开。固定字体编辑视图基线与原 DOCX 预览基线分开核对。自动分页及 PDF 在 R1-12，原生 DOCX 导出在 R1-13。

预览、批注和编辑的最终交付要求是同一份保留 Office 样式的实时文档画布：页面尺寸与边距、字体、段落、表格和图片布局保持一致，输入后即时重排及更新分页。当前连续输入是 R1-11 的阶段实现；统一分页画布在 R1-12 集成并于 R1-14 验收。输入内核是可替换适配器，不能成为另一套文档源或决定最终版式。

R1-12 输入、预览和批注共用[自研页面画布](pagination-rendering.md)，没有引入第二个编辑状态或第三方分页器。组合输入期间保留输入法临时 DOM，组合结束后通过同一核心事务提交并重新分页。
